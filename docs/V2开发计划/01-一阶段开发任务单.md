# V2 一阶段开发任务单：数据模型与文件层重构

本文是一份可以直接交给其他 AI 执行的一阶段任务单。

## 1. 阶段目标

一阶段只做 V2 底层数据模型和 Inbox 文件层重构，不做完整 UI 重设计，不做 AI Enrich 页面，不做视频解析。

目标结果：

- 新 Inbox 捕获停止生成 frontmatter。
- Markdown 文件保持纯净。
- Todo / Collect / Delete 进入 sidecar metadata。
- Home 卡片列表改为从 Markdown 文件 + sidecar metadata 合成。
- 旧 frontmatter 文档可以继续读取，但不再作为新写入格式。

## 2. 必须遵守的边界

- 不修改 `docs/V2-handoff/`。
- 不引入 Enrich 新流程。
- 不实现视频解析。
- 不做 Article 大改版。
- 不把 App 状态写入 Markdown。
- 不把文件名当作卡片主标题。
- 不把旧 V1 frontmatter 字段迁移进新文件。

## 3. 需要新增或调整的数据模型

建议新增文件：

```text
src/shared/v2-types.ts
src/shared/v2-markdown.ts
src/shared/v2-card-metadata.ts
```

### 3.1 CardMetadata

```ts
export type V2CardKind = 'note' | 'todo'
export type V2CardBucket = 'inbox' | 'collected' | 'deleted'

export interface CardMetadataFile {
  version: 1
  items: Record<string, CardMetadata>
}

export interface CardMetadata {
  kind: V2CardKind
  bucket: V2CardBucket
  createdAt: string
  updatedAt: string
}
```

key 建议：

```text
inbox file basename，例如 20260428-001.md
```

不要用旧 slug 语义，也不要依赖 frontmatter title。

### 3.2 V2InboxCard

```ts
export interface V2InboxCard {
  id: string
  filename: string
  path: string
  title: string
  hasTitle: boolean
  preview: string
  kind: V2CardKind
  bucket: V2CardBucket
  createdAt: string
  updatedAt: string
  raw: string
}
```

标题规则：

- 第一行是 `# Heading`：`title = Heading`，`hasTitle = true`。
- 第一行不是 heading：`title = ''`，`hasTitle = false`。
- 文件名只作为次级 debug / path 信息，不作为主标题。

摘要规则：

- 从 Markdown 正文去掉开头 H1 后生成摘要。
- 不解析 frontmatter 作为摘要来源。
- 摘要长度由现有 Home 卡片控制即可。

## 5. IPC 任务

需要在 `electron/main.ts` 增加或调整：

### 5.1 路径 helper

新增：

```ts
getAiInboxRoot()
getV2InboxPath()
getMetadataPath()
getCardsMetadataPath()
ensureV2Directories()
```

兼容注意：

- 当前默认 `inboxPath` 是 `~/ai-inbox`，V2 应将新捕获写入 `~/ai-inbox/inbox/`。
- 不要让 `~/ai-inbox/enrich/` 或 `~/ai-inbox/metadata/` 被 `inbox:list` 当成文章目录。

### 5.2 metadata helper

新增：

```ts
readCardMetadataFile()
writeCardMetadataFile(file)
ensureCardMetadataForFile(filename, stats)
updateCardMetadata(filename, patch)
repairCardMetadata()
```

一致性规则：

- Markdown 文件存在但 metadata 缺失：自动补默认 metadata。
- metadata 指向文件不存在：列表不显示；可以保留，后续清理。
- 文件在外部改名：视为旧文件消失、新文件出现。

### 5.3 IPC contract

保留兼容旧接口的同时，优先新增 V2 接口：

```ts
ipcMain.handle('v2:inbox:capture', (_, content: string) => ...)
ipcMain.handle('v2:cards:list', () => ...)
ipcMain.handle('v2:cards:set-bucket', (_, filename: string, bucket) => ...)
ipcMain.handle('v2:cards:set-kind', (_, filename: string, kind) => ...)
ipcMain.handle('v2:file:read-inbox', (_, filename: string) => ...)
ipcMain.handle('v2:file:write-inbox', (_, filename: string, raw: string) => ...)
```

为了降低页面改动量，也可以让旧接口暂时代理到 V2：

- `mcp:process-input` 内部改为纯 Markdown capture。
- `inbox:list` 返回兼容现有 store 的 card-like 数据。
- `inbox:set-bucket` 改为更新 sidecar metadata。
- `inbox:read-raw` / `inbox:write-raw` 仍按文件名读取和保存 raw。

关键点：旧接口可以兼容，但不能继续写 frontmatter。

## 6. renderer / preload 任务

需要同步调整：

- `electron/preload.ts`
- `src/env.d.ts`
- `src/lib/browser-electron-api.ts`
- `src/stores/inbox.ts`

最低要求：

- `processInput(type, content)` 调用后生成纯 Markdown。
- `listInbox()` 能拿到 V2 卡片数据。
- `setBucket()` 只改 metadata。
- `readRawFile()` / `writeRawFile()` 可以读写纯 Markdown。
- dev browser API 不报缺失接口。

## 7. Home store 改造

当前 `src/stores/inbox.ts` 依赖：

- `frontmatter`
- `getDocumentTags`
- `resolveDisplayTitle`
- `getDocumentBucket`
- `enrichStatus`

一阶段需要改成：

- title 来自 `extractMarkdownCardTitle(raw)`。
- preview 来自 `extractMarkdownPreview(raw)`。
- bucket 来自 sidecar metadata。
- kind 来自 sidecar metadata。
- 删除 store 层 enrichStatus 依赖。
- tags 可删除，或置为空数组用于兼容现有模板。

如果为了减少 UI 改动暂时保留 `InboxCard` 字段：

```ts
enrichStatus: 'none'
tags: []
type: metadata.kind
```

但这只是兼容字段，不能再表示真实 V2 状态。

## 8. Home 页面最小必要改动

一阶段不重做首页视觉，只做避免 V1 状态泄漏的必要调整：

- 删除卡片上的 enrich tag。
- 卡片没有 title 时，不渲染 `<h3>`。
- Collect / Delete 操作继续可用，但调用 metadata。
- 输入提交后提示改为“已保存到 Inbox”。
- 不新增 AI 按钮，或只放禁用占位；Enrich 放到后续阶段。

## 9. Article 页面一阶段处理

一阶段不做 Article 大改版，但必须避免新文件保存时被重新注入 frontmatter。

最低要求：

- 打开 V2 纯 Markdown 文件时，`frontmatterText` 为空。
- 保存 V2 文件时，如果原文件无 frontmatter，就只写 `bodyMarkdown`。
- 禁止 `syncBodyH1ToFrontmatter()` 对无 frontmatter 的 V2 文件生成 frontmatter。
- Collect / Delete 按钮如果仍存在，暂时只对 legacy 文档有效，或后续阶段删除。

建议一阶段不要重构整个 Article UI，避免扩大风险。

## 10. 旧功能处理

一阶段应删除或停用：

- `processInputPipeline()` 中的 `buildFrontmatter(...)` 新写入路径。
- 捕获时自动插入 `# title`、`## 原文`。
- 捕获时自动 tags / type / source / bucket / enrichStatus。
- `scheduleAutoEnrich()` 在新捕获后的调用。

一阶段可保留：

- `parseFrontmatter()`，用于旧文档兼容。
- `buildFrontmatter()`，仅旧文档编辑兼容，不用于新捕获。
- `ai-enrichment.ts`，暂时不改或只断开入口。

## 11. 难点与关键点

### 难点 1：旧接口兼容

当前 Home、Article、store 都在吃 `InboxDocument.frontmatter`。如果一次性全部重写，风险较大。

处理方式：

- main process 先提供 V2 数据。
- store 层做兼容映射。
- UI 后续阶段逐步删字段。

### 难点 2：路径从 slug 变 filename

V1 用 slug 读写文件，V2 更接近 filename / path。

处理方式：

- 一阶段 Inbox 内部可以继续把 filename 去掉 `.md` 后当作临时 id。
- 新增 V2 IPC 时使用 filename。
- Workspace 阶段再升级为 encoded path。

### 难点 3：Article 自动同步 frontmatter

当前 Article 保存链路会同步 body H1 到 frontmatter。

处理方式：

- 增加 `isV2PlainMarkdown` 判断：原始文件没有 frontmatter 时，不执行任何 frontmatter 同步。
- `currentRawDocument` 对 V2 文件直接等于 `bodyMarkdown`。

### 难点 4：metadata 与文件不一致

用户可能在外部删除或改名 Markdown 文件。

处理方式：

- list 时修复缺失 metadata。
- metadata 指向缺失文件时不展示。
- 不做复杂文件身份追踪。

## 12. 验收清单

必须手动验证：

- 新输入普通文本，生成文件没有 frontmatter。
- 新输入 URL，生成文件正文仍是原始 URL 或原始输入，不包 `# title` / `## 原文`。
- 新输入 `todo xxx` 不再追加到月度 todo frontmatter 文档；应创建普通 Markdown 捕获，并由 metadata kind 表示 todo。
- Collect 卡片后，Markdown 文件内容不变。
- Delete 卡片后，Markdown 文件内容不变。
- 刷新应用后，卡片状态仍然存在。
- 旧 frontmatter 文档仍能在列表中显示并打开。
- Home 卡片不再显示 Enrich 状态。
- 不触发自动 AI enrich。

建议运行：

```bash
npm run typecheck
```

如本地已有 unrelated TypeScript 错误，需在交付说明中明确列出，不要混淆为本阶段引入的问题。
