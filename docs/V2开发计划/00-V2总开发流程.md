# AI-inbox V2 总开发流程

本文是 V2 开发的总路线。主要参考 `docs/V2-handoff/`，不再沿用 V1 的 frontmatter / Enrich 状态模型。

## 0. V2 产品边界

V2 的核心定位：

```text
本地 Markdown 知识库 + 临时 Inbox 捕获 + 独立 AI Enrich 链接解析任务台
```

必须坚持的边界：

- Markdown 文件是用户资产，保持纯净。
- App 状态进入 sidecar metadata，不写进 Markdown。
- 新捕获内容不生成 frontmatter。
- Todo / Collect / Delete 等卡片状态不写 Markdown。
- Enrich 任务独立存在，不自动合并到文章。
- 多 workspace 是 V2 的核心能力，App 自有的 `inbox/` 和 `enrich/outputs/` 也可以作为 workspace 打开。
- AI Enrich 放到主流程后期实现。
- 视频解析放到 Enrich 的最后阶段实现。

## 1. 阶段一：数据模型与文件层重构

目标：先切断 V1 frontmatter 依赖，为后续 UI 和 workspace 改造打地基。

范围：

- 新增 V2 Markdown 文件模型。
- 新增 sidecar card metadata。
- 调整 Inbox 捕获逻辑，停止写 frontmatter。
- 调整 Inbox 列表读取逻辑，从 Markdown + metadata 合成卡片。
- 保留 legacy frontmatter 读取兼容，但不再作为新模型。

建议落点：

- `src/shared/` 新增 V2 类型与 Markdown 工具。
- `electron/main.ts` 新增 metadata 读写 helper。
- `electron/preload.ts`、`src/env.d.ts`、`src/lib/browser-electron-api.ts` 补齐 IPC contract。
- `src/stores/inbox.ts` 改为消费 V2 card view model。

验收标准：

- 输入 `待阅读 https://abcdefg` 后，新 Markdown 文件正文严格等于这一行。
- 新 Markdown 文件没有 frontmatter。
- Collect / Delete / Todo 只修改 `~/ai-inbox/metadata/cards.json`。
- Home 卡片标题只来自第一行 Markdown heading；非 heading 第一行不作为标题。
- V1 旧文档可以继续打开，但新写入不再生成 V1 字段。

## 2. 阶段二：Workspace 与统一 Sidebar

目标：把 App 从单一 Inbox 文件夹升级为多 Markdown workspace。

范围：

- 新增 workspace 配置模型。
- 支持添加、移除、启用、禁用 workspace。
- 内置 workspace：
  - `~/ai-inbox/inbox/`
  - `~/ai-inbox/enrich/outputs/`
- 新增 workspace 文件树读取能力。
- 抽出三页共用的 V2 Sidebar。

建议落点：

- `electron/main.ts` 新增 `workspace:*` IPC。
- `src/stores/workspace.ts` 管理 workspace 和文件树。
- `src/components/` 新增 `AppSidebar.vue` 或等价组件。
- `src/router/index.ts` 为 path-based article route 做准备。

验收标准：

- Sidebar 不显示 logo / AI-inbox 品牌标题 / Local。
- Sidebar 顶部只保留 macOS traffic lights 空间。
- Sidebar 一级入口只有 `Inbox`、`AI Enrich` 等核心入口。
- Workspace 区能显示 Inbox、Enrich Output 和用户添加的本地 Markdown 目录。
- 点击 workspace 文件能打开 Article 页面。

## 3. 阶段三：Home / Inbox V2 改造

目标：保留现有首页大结构，但换成 V2 语义和 V2 数据来源。

范围：

- 保留 Quick Capture、瀑布流卡片、Calendar、Scratchpad。
- Quick Capture 提供 `Inbox` 和未来 `AI` 两个流向。
- 第一轮可先禁用或占位 `AI` 按钮，等 Enrich 阶段再接入。
- 卡片状态来自 sidecar metadata。
- 删除普通卡片上的 Enrich 状态展示。
- 删除 frontmatter tags 展示或降级为旧文档兼容展示。
- 搜索以标题摘要和正文摘要为主。

验收标准：

- 首页没有邮箱语义。
- 普通卡片不显示 `Raw / Fetching / Success / Failed`。
- 文件名不作为卡片主标题。
- Deleted 默认隐藏，只在 Deleted 筛选中显示。
- Calendar 只服务 Inbox 内容筛选，不变成日程系统。

## 4. 阶段四：Article 纯 Markdown 工作台

目标：Article 页面只处理 Markdown 编辑 / 阅读，不再处理文章属性。

范围：

- 路由从 slug-based 过渡到 encoded path 或 file id。
- 读取任意 workspace 中的 Markdown 文件。
- 删除 frontmatter panel。
- 删除 frontmatter parse error UI。
- 删除 `syncBodyH1ToFrontmatter` 等标题同步逻辑。
- 删除文章级 Enrich 状态。
- 顶部改为紧凑 Markdown toolbar。
- 底部状态栏显示保存状态、格式、字数、行数、更新时间。

验收标准：

- 打开纯 Markdown 文件时不生成 frontmatter。
- 保存后只保存用户正文。
- 外部编辑冲突提示仍然可用。
- Article 页面不显示文档属性面板。
- Article 页面不显示文章级 AI / Enrich 状态。

## 5. 阶段五：AI Enrich 任务台

目标：新增独立 AI Enrich 页面，但不影响普通文章和 Inbox。

范围：

- 新增 `/ai-inbox` 页面。
- 新增 `~/ai-inbox/enrich/tasks.json`。
- 支持 URL + instruction 创建任务。
- 支持平台识别：Generic Link、Bilibili、YouTube、Douyin。
- 第一版先实现通用链接任务与 Markdown output。
- 任务状态只在 AI Enrich 页面显示。
- 成功结果写入 `~/ai-inbox/enrich/outputs/`。
- 支持 Open Result / Copy Markdown / Retry / Delete。
- Article 选中链接创建 Enrich 任务放在本阶段后半段。

验收标准：

- 创建任务不会创建 Inbox 卡片。
- 创建任务不会修改源 Markdown。
- 任务列表刷新后仍可恢复。
- Output 文件可以作为普通 Markdown 打开。
- `fromPath` 只是弱引用，文件被移动或改名时允许断开。

## 6. 阶段六：Enrich 结果保存与 workspace 串联

目标：让 Enrich output 能进入用户 workspace，但仍然不自动合并。

范围：

- `Save as Article` 保存 output 到指定 workspace。
- 可选择文件名和目标目录。
- Enrich Output 内置 workspace 自动显示新结果。
- 后续可增加追加到已有文章，但不作为第一版必须项。

验收标准：

- 保存为文章是显式用户操作。
- 不自动覆盖源文章。
- 不自动把摘要插回当前 Article。
- 保存后的文件是纯 Markdown。

## 7. 阶段七：视频解析 adapter

目标：在 Enrich 稳定后再做视频专项解析。

范围：

- Bilibili adapter。
- YouTube adapter。
- Douyin adapter。
- transcript / metadata / summary 的独立失败处理。
- adapter 产物仍然写入 Enrich output，不写源文章。

验收标准：

- 视频解析失败只影响对应 task。
- 普通链接解析能力不被视频 adapter 影响。
- 没有 transcript 时能给出明确失败或降级结果。

## 8. V1 功能处理策略

删除：

- 新文档 frontmatter 生成。
- 捕获后自动 enrich。
- enrich 成功后自动合并到文章。
- 普通卡片上的 enrich 状态。
- Article frontmatter 属性面板。

降级为兼容：

- `parseFrontmatter` 只用于旧文档读取保护。
- `tags`、`titleSource`、`aiTitle`、`contentTitle` 不再作为 V2 状态。
- `archivePath` 不再作为主流程，后续由 workspace 保存替代。
- MCP V1 工具输出要逐步改成纯 Markdown 捕获或 Enrich task。

## 9. 推荐实施原则

- 每个阶段都要保证 Markdown 纯净性可验证。
- 先改数据合同，再改 UI。
- 先让本地文件稳定，再做 Enrich。
- Enrich 不参与 Article 保存链路。
- 视频解析必须等 Enrich task / output / retry / error 机制稳定后再做。
