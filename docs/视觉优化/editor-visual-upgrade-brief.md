# 编辑器视觉升级 Brief

## 背景

当前编辑器在功能上已经基本可用：

- fixed toolbar 可用
- bubble menu 可用
- slash menu 可用
- link popover 可用
- 内容区排版、滚动层、frontmatter 浮层已经有基础
- 内容区样式与编辑器 chrome 也已经开始分层

现在的主要问题已经不是“功能能不能用”，而是：

**整体观感还不够产品化，距离 Tiptap 官方 `Simple Editor` / `UI Components` 那种干净、轻盈、统一的质感还有差距。**

这次任务的目标不是继续修功能，而是做**视觉升级**。

---

## 本轮目标

把当前编辑器从“工程可用态”提升到“产品观感明显更好”的状态。

重点是：

1. 更统一的视觉语言
2. 更舒服的留白和密度
3. 更像一个成熟的编辑器，而不是多个组件拼起来
4. 更接近 Tiptap `Simple Editor` / `UI Components` 的气质

---

## 不是本轮重点

这次不要把精力放在这些方向：

1. 不要大改保存逻辑
2. 不要重写 markdown 流程
3. 不要扩展大量新功能
4. 不要恢复 `table`
5. 不要重构 frontmatter 逻辑
6. 不要重新引入 `@nuxt/ui`

如果发现结构问题，只做**最小必要改动**。

---

## 设计方向

### 目标气质

参考 Tiptap 官方：

- `Simple Editor`
- `Slash Dropdown Menu`
- `Link Popover`
- `Bubble Menu`

希望达到的感觉：

1. 轻
2. 干净
3. 有秩序
4. 留白克制
5. 浮层像一套系统
6. 内容区更像“写作表面”，而不是普通 textarea 放大版

### 不希望出现的感觉

1. 工具栏太厚重
2. Bubble 像缩小版 fixed toolbar
3. Slash 像自定义弹窗
4. Link Popover 像功能条拼接块
5. 内容区像“很多 CSS 规则叠起来的结果”

---

## 优先改进区域

### 1. Fixed Toolbar

目标：

- 更轻
- 更整齐
- 更像编辑器顶部 chrome
- 图标、hover、active 状态更统一

建议：

1. 优化高度、间距、分组节奏
2. 弱化背景和边框厚重感
3. 让按钮 hover / active 更干净
4. 让图标和文字 fallback 的视觉重量更一致

---

### 2. Bubble Menu

目标：

- 真正像轻量悬浮工具条
- 更接近官方 Bubble Menu 的气质
- 不是“一个白色缩小工具栏”

建议：

1. 降低容器存在感
2. 减小按钮之间的机械感
3. 让 hover / active 更柔和
4. 让它视觉上更像“贴着选区浮着”

---

### 3. Slash Menu

目标：

- 更像官方 dropdown
- 更轻、更简洁
- 更像命令面板，而不是功能列表

建议：

1. 宽度、行高、padding 更收敛
2. 每行只保留 `icon + title`
3. selected 状态要克制但明确
4. icon 区域宽度和文字对齐更整齐

---

### 4. Link Popover

目标：

- 更像标准 popover
- 输入框成为主角
- 行为简单清晰

建议：

1. 提升输入区质感
2. 操作按钮更清楚，不要挤
3. 整体更接近“编辑链接”的弹出卡片，而不是工具条延伸

---

### 5. 内容区排版

目标：

- 更像真正写作界面
- 标题、段落、列表、引用、代码块之间有更好的节奏
- 空白区域有“画布感”

建议：

1. 调整段落和标题的垂直节奏
2. 优化 blockquote / code block / hr 的存在感
3. 让内容区整体排版更统一
4. 让空白区与正文内容之间的心理边界更自然

---

## 视觉系统要求

本轮要尽量把这些统一起来：

1. 圆角体系
2. 阴影体系
3. 边框透明度
4. hover 背景
5. active 背景
6. icon 尺寸
7. 控件高度
8. 字号层级

特别注意：

- fixed toolbar
- bubble menu
- slash menu
- link popover

这四者必须看起来像**同一个设计系统**出来的。

---

## 内容主题约束

当前内容区已经有主题基础设施：

- `contentTheme`
- `data-content-theme`
- `default / serif`

这次视觉升级时：

1. 不要破坏这套内容主题入口
2. 可以顺手优化 `default` 主题的排版和变量
3. 但不要把主题系统重新做回全局 `:root` 写死

---

## 宿主边界

继续保持下面这个原则：

1. `ArticlePage` 只负责页面布局和 frontmatter 面板
2. `ArticleBodyEditor` 是薄包装
3. 编辑器内部视觉尽量留在 `src/modules/rich-editor`

不要再把编辑器样式责任推回宿主页。

---

## 执行方式

请按下面顺序推进：

1. 先做一次视觉审计
   - 指出当前最丑/最不统一的 5-8 个点

2. 再直接改代码
   - 不要只给建议

3. 每次改动优先提升整体感
   - 不要沉迷局部微调

4. 保持小步可验证
   - 优先做最影响观感的地方

---

## 交付要求

完成后请交付：

1. 修改了哪些文件
2. 视觉升级重点改了哪几块
3. 你参考了哪些 Tiptap 官方组件/模板的气质
4. 当前还剩哪些不够满意的视觉点
5. `npm run typecheck` 结果
6. 如有运行，附 `npm run build` 结果

---

## 评审标准

后续 review 时会重点看：

1. toolbar 是否更轻更统一
2. bubble 是否更像真正悬浮工具条
3. slash 是否更像官方 dropdown
4. link popover 是否更像标准 popover
5. 内容区排版是否更有写作质感
6. 四类浮层是否像同一套系统
7. 是否没有破坏现有功能闭环

---

## 一句话目标

这次不是“继续修编辑器”，而是：

**把当前编辑器做成一个更漂亮、更统一、更像成熟产品的写作界面。**
